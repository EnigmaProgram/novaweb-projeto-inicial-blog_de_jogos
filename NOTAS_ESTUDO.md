# 1. O que é um Projeto de Software?

## 1.1 O que difere um "Projeto de Software" de um "Script/Código isolado"?
Um projeto de software é uma estrutura muito mais complexa, logo, mais completa, ela não é uma estrutura rápida de produzir, nela é necessário planejamento, definição de requisitos, desenvolvimento, testes e entrega. Costuma possuir um objetivo específico e deve ser organizado para coolaboração.

Já o script ou código isolado é mais simples, nele ocorre a resolução de uma tarefa específica, podendo ser bem menor e exigindo bem menos planejamento e organização de um projeto.

## 1.2 Ciclo de Vida Básico de um Projeto de Software
Levantamento de Requisitos / Escopo

Nessa parte é definido o que o sistema precisa fazer. A equipe entende o que o cliente está pedindo e decide quais funcionalidades vão fazer parte do projeto. Também é importante definir o que não será feito, para evitar mudanças desnecessárias depois.

Desenvolvimento / Codificação

É quando começa a parte de programação. Os desenvolvedores pegam o que foi planejado nos requisitos e começam a transformar essas ideias em código e funcionalidades.

Testes / Qualidade

Depois que as funcionalidades são desenvolvidas, é preciso testar o sistema para descobrir possíveis erros. Os testes também servem para verificar se o programa realmente está fazendo o que foi pedido.

Entrega / Implantação

É quando o software já está pronto e pode ser entregue ao cliente ou colocado para os usuários utilizarem. Dependendo do sistema, também pode ser necessário instalar e configurar o programa.

## 1.3 Por que definir um escopo fechado antes de iniciar a codificação?

Definir o escopo antes de começar a programar é importante porque deixa mais claro para a equipe o que precisa ser feito. Se o projeto começar sem ter isso definido, podem aparecer novas ideias ou pedidos no meio do desenvolvimento, fazendo a equipe ter que mudar o que já estava fazendo.

Isso pode aumentar o tempo de desenvolvimento e acabar atrasando a entrega. Por isso, ter um escopo definido ajuda a organizar melhor o trabalho e facilita o cumprimento dos prazos.

# 2. Análise de Sites

## 2.1 IGN Brasil
### Objetivo

A IGN Brasil é um portal de notícias e entretenimento voltado ao universo dos jogos, filmes, séries, animes e tecnologia. Seu principal objetivo é informar os usuários por meio de notícias, análises, reviews e conteúdos especiais.

### Estrutura da Página
#### Header (Cabeçalho)

O cabeçalho é simples e limpo, contendo:

Logotipo da IGN Brasil;
Botão para expandir ou recolher o menu lateral.

Ao rolar a página, também é possível acessar a barra de pesquisa, permitindo localizar conteúdos específicos.

#### Nav (Navegação)

A navegação é feita por um menu lateral fixo, organizado por categorias como:

Essa organização facilita o acesso rápido aos diferentes assuntos do portal.

#### Main (Conteúdo Principal)

A área principal apresenta:

notícias em destaque utilizando imagens grandes;
cards organizados lado a lado;
seção "Mais destaques";
diversas matérias distribuídas verticalmente conforme o usuário navega pela página.

As imagens ocupam bastante espaço visual e são acompanhadas de títulos chamativos, tornando fácil identificar os conteúdos mais relevantes.

#### Footer (Rodapé)

O rodapé da IGN Brasil é bastante simples e minimalista. Ele apresenta:

Logotipo da empresa Ziff Davis;
Informação de direitos autorais ("© 2026");
Identificação de que a IGN Brasil pertence ao grupo Webedia.

O design segue o mesmo padrão limpo do restante do site, contendo apenas as informações institucionais essenciais, sem excesso de links ou elementos visuais.

### Análise da UX

A IGN Brasil apresenta uma interface moderna, limpa e organizada. O menu lateral concentra toda a navegação do portal, permitindo acessar rapidamente qualquer categoria. O destaque para imagens grandes e manchetes facilita a identificação das principais notícias.

A barra de pesquisa também está disponível, permitindo que o usuário encontre conteúdos específicos quando necessário. A combinação entre menu por categorias e pesquisa oferece uma navegação eficiente e intuitiva.

Em resumo, ambos oferecem uma boa experiência ao usuário, porém a IGN prioriza uma interface mais limpa e visual, enquanto o Adrenaline aposta em disponibilizar mais opções de navegação e acesso às diferentes áreas do portal.

# 3. Investigação de UX e HTML Semântico

## Qual a relação entre "Design em blocos" e "HTML Semântico"?

O design em blocos consiste em organizar a interface em áreas bem definidas, como cabeçalho, menu de navegação, conteúdo principal e rodapé. Já o HTML semântico utiliza elementos específicos, como <header>, <nav>, <main>, <section>, <article> e <footer>, para representar essas áreas no código.

Dessa forma, o design em blocos serve como um planejamento visual da página, enquanto o HTML semântico transforma essa organização em uma estrutura lógica e compreensível tanto para os navegadores quanto para mecanismos de busca e tecnologias assistivas, como leitores de tela.

## Qual a importância de planejar a estrutura semântica antes de escrever o código CSS/HTML?

Planejar a estrutura semântica antes de desenvolver o código é importante porque permite organizar corretamente o conteúdo da página desde o início. Com essa estrutura definida, torna-se mais fácil aplicar estilos em CSS, manter o código organizado e facilitar futuras alterações. Além disso, o uso de HTML semântico melhora a acessibilidade, ajuda os mecanismos de busca a compreenderem o conteúdo da página e proporciona uma experiência mais eficiente para os usuários. Portanto, esse planejamento reduz retrabalho e contribui para um desenvolvimento mais organizado e de melhor qualidade.
